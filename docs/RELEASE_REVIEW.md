# Public release review

Reviewed the repository for its initial public source release. The reviewed
implementation and release preparation are included in one squashed root commit.

## Findings addressed

- Async saves now resolve existing user paths and parent directories with their
  actual casing. Previously a save could create a separate lowercase file or
  fail to find a mixed-case parent.
- Async web directory creation and rename use the same path resolution as
  synchronous operations.
- Both rename fronts update the same user case map. Renaming a directory keeps
  its existing mixed-case descendants addressable through logical paths.
- Case-map lookups and rename updates share a mutex. Previously a native rename
  could mutate an unordered map while another thread was reading it, even for
  unrelated paths. Removal leaves stale mappings to the existing resolver,
  which already falls back when the physical path no longer exists.
- Native async whole-file load reports SDL submission/open failures through its
  callback. Previously a file removed after indexing could terminate the
  process through the fatal-submission branch.
- Web asset-change callbacks update the affected handle while keeping the shared
  asset index immutable, as specified by the manifest snapshot contract.
  Previously they also wrote shared metadata without synchronization, racing
  concurrent path-info queries and opens in pthread applications.
- Manifest parsing performs its existing minimum-size validation before
  computing the end pointer, avoiding null-pointer arithmetic on an empty
  manifest.
- The JavaScript library linker argument quotes the source path so a checkout
  directory containing spaces is usable.
- README and design documentation now describe current user case-map behavior,
  dependency lookup, async failure semantics, and storage-space reporting.
- Added GPL version 3 or later licensing, the full license text, and SPDX
  identifiers in source, headers, examples, and build/server scripts.
- Generated build directories and Python bytecode are ignored. Removed the
  existing generated Python bytecode from the source tree.

## Privacy review

Reviewed tracked source, headers, examples, build files, server code, and
Markdown documentation. Scanned all 35 historical file blobs reachable from
existing branches and tags for personal paths, usernames, hostnames, email
addresses, credential patterns, and private keys. No machine- or user-specific
content was found in those files. Runtime paths come from configuration or SDL.
The reference server defaults to the generic loopback address.

The public branch starts with one squashed commit using a neutral contributor
identity. Local Git metadata still contains the private remote configuration,
and remote-tracking refs and reflogs can retain earlier history and identities.
A public source distribution should contain project files rather than the
local `.git` directory, generated bytecode, build caches, or logs. The source
archive prepared with this review excludes those files and uses neutral tar
ownership and timestamps.

## Validation

- Linux Release build with SDL 3.4.16, all five examples, and compiler warnings
  enabled: successful, with no warnings. Builds used 24-way parallelism.
- Ran all five native examples against a mixed-case asset filename: successful.
  Confirmed the user-save example wrote its expected contents in an isolated
  preference directory.
- Emscripten 6.0.10 development toolchain: built the library and all five web
  examples, including async-only and Asyncify executables.
- Ran all five web examples through the reference asset server in the
  collaborative browser: successful exit status, no aborts. Callback and
  coroutine examples each reported reading 16 bytes.
- Checked the final diff for whitespace errors. No new tests were added.

## Release limits

Windows, macOS, and browser pthread execution were not validated. The existing
examples do not cover async mixed-case saves/renames, concurrent case-map
access, or live asset-version changes, so those fixes have code review and
build coverage only. Browser runs
do not establish exhaustive cache eviction, offline behavior, persistence across
process restarts, or failure-path coverage.

The SDL generic storage backend reports `SDL_MAX_UINT64` for unknown remaining
space. The forwarding API is not an actual free-space or browser-quota query.
Timestamp setting has whole-second precision.

Existing documented constraints remain: one context per process/page lifetime,
caller sequencing for conflicting paths, trusted asset trees and symlinks,
best-effort asset caching, direct IDBFS persistence, and no atomic save, timeout,
retry, cancellation, or automatic shutdown drain. CMake supports integration
through `add_subdirectory`; no standalone install/export package is provided.

The files are prepared for a public source release. Publish the squashed
branch and validate any additional platforms being claimed as supported by
the release.
